# HomeBot 🏡

Помічник будинків: приватна реєстрація мешканців і голосування в кількох групах Telegram.
TypeScript, Cloudflare Workers, D1. Структура та production-команди повторюють підхід deye-monitor. Окремий сервер і Mini App не потрібні.

## Перша версія

- Реєстрація через кнопку під голосуванням: ім’я → номер квартири → власник / орендар. Група визначається з цього голосування. Якщо підключена одна група, достатньо `/start`. Дані вводяться тільки в особистому чаті з ботом.
- Адміністратор підтверджує або відхиляє заявку приватними кнопками; `/pending` дозволяє повторно відкрити заявки.
- Адміністратор відкриває `/start` → «🗳 Створити голосування». Якщо груп кілька, бот спочатку просить обрати групу, потім питання й варіанти окремими повідомленнями. Назва групи також показується в попередньому перегляді. «Готово» показує попередній перегляд, «✅ Опублікувати в групі» публікує. До підтвердження нічого не надсилається мешканцям.
- Чернетка зберігається в D1. «Скасувати» або `/cancel` видаляє її; старі кнопки не впливають на нову чернетку.
- `/poll` без аргументів також запускає діалог. Формат `/poll Питання | Так | Ні | Утримався` доступний для швидкої публікації, якщо підключена рівно одна група. За кількох груп потрібно скористатися діалогом із вибором групи.
- Підтверджені мешканці голосують кнопками в групі, підтвердження вибору бачить лише користувач.
- Незареєстрованому бот пропонує відкрити реєстрацію у власному чаті всередині Telegram. Потрібно натиснути «Почати». Анкети в групі немає.
- Реєстрації та підтвердження ізольовані за групами. Один Telegram-акаунт може зареєструватися в кількох будинках із різними квартирами. Підтвердження в одній групі не дає доступу до голосувань іншої.
- Один голос від квартири в межах конкретної групи; кілька мешканців можуть зареєструватись. Змінити вибір до закриття може лише той мешканець, який подав голос від квартири.
- `/results ID`: підрахунок для адміністратора. `/close ID`: закрити й замінити повідомлення голосування підсумками без кнопок.
- Інтерфейс українською. Числові квартири 1–99999 нормалізуються: `001` і `1` — одна квартира.

## Налаштування

Потрібен Node.js 22.18+ (або актуальний LTS), npm та обліковий запис Cloudflare.

```sh
npm install
npx wrangler login
npx wrangler d1 create homebot
```

У `wrangler.toml` замінити нульовий `database_id` на ID **нової** бази. Базу та токен deye-monitor не використовувати.

```sh
cp .dev.vars.example .dev.vars
```

Заповнити `.dev.vars` для локальної роботи. Username бота визначається автоматично через Telegram `getMe`:

| Змінна | Значення |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен нового бота від BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | Випадковий секрет, наприклад результат `openssl rand -hex 32` |
| `ADMIN_TELEGRAM_USER_ID` | Числовий Telegram ID адміністратора |

Адміністратор має першим відкрити бота та натиснути «Почати», щоб бот міг надсилати заявки. Додайте бота до групи та дозвольте надсилання повідомлень. Адміністратору прийде приватна заявка з назвою групи, її ID та користувачем, який додав бота. Лише адміністратор може натиснути «Підключити» або «Відхилити». До підтвердження бот не публікує голосування в цій групі. Вимикати privacy mode не потрібно: бот не обробляє звичайні повідомлення групи.

```sh
npm run db:migrate
npm run typecheck
npm test
npm run dev
```

Локальний endpoint: `POST /telegram/webhook` із заголовком `X-Telegram-Bot-Api-Secret-Token`. Telegram потребує публічного HTTPS endpoint; звичайний localhost не отримуватиме оновлення.

## Production, як у deye-monitor

Додати всі три змінні через Cloudflare Dashboard → Worker → Settings → Variables and Secrets або `npx wrangler secret put НАЗВА`. Токен і webhook-секрет зберігати як secrets. У Workers Builds вони потрібні також у build environment, якщо використовується автоматична реєстрація webhook.

```sh
npm run db:migrate:remote
npm run deploy
```

Після отримання URL Worker задати в середовищі запуску скрипта `APP_URL` (HTTPS origin без шляху), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, потім:

```sh
npm run webhook
```

Для наступних релізів із цими змінними доступна команда `npm run deploy:production` (міграції → Worker → webhook). Поточний проєкт не виконує деплой автоматично. Скрипт встановлює `max_connections=1` для послідовної доставки оновлень та `allowed_updates`, включно з `my_chat_member` для заявок на підключення. Після оновлення потрібно перереєструвати webhook. Якщо бота вже додали раніше, видаліть і додайте його до групи знову, щоб отримати подію підключення.

## Керування групами

`/start` адміністратора → «🏘 Мої групи» показує всі заявки та підключення з кнопками. Підключених груп може бути кілька. Від’єднання потребує окремого підтвердження, закриває відкриті голосування тільки цієї групи й зберігає її реєстр та результати. Старі кнопки голосування більше не приймають голосів. Бот фізично залишається у групі; її можна підключити знову з цього меню. Після повторного підключення старі голосування не відкриваються.

Якщо бота видалили з групи, підключення автоматично вимикається. Повторне додавання створює нову заявку. Зміна прав бота в уже підключеній групі не створює повторну заявку. Канали не підтримуються.

Міграція `0003_multiple_groups.sql` зберігає старі голоси й реєстр. Стару групу потрібно підключити явно; старі відкриті опитування закриваються. За наявності рівно однієї групи в історії реєстрації прив’язуються до неї; якщо група невідома, старі записи зберігаються під `chat_id=0` без права голосувати, а мешканці реєструються заново. `TELEGRAM_CHAT_ID` більше не використовується.

## Перевірка в Telegram

1. Адміністратор запускає бота, додає його у дві групи та підтверджує обидві заявки в особистому чаті.
2. Переконатися, що дані не з’являються у групі. Спробувати підтвердити заявку не з акаунта адміністратора — дія має бути заборонена.
3. Адміністратор відкриває `/start` → «Створити голосування», обирає групу, вводить питання та два варіанти, переглядає й підтверджує публікацію. Інший акаунт відкриває реєстрацію під голосуванням; адміністратор підтверджує заявку.
4. Зареєстрований користувач голосує і змінює вибір; інший мешканець тієї ж квартири не може перезаписати його голос.
5. Незареєстрований користувач отримує перехід до приватної реєстрації.
6. `/close ID` показує підсумки, подальші голоси не приймаються.
7. Підтверджений мешканець однієї групи не може голосувати в іншій без окремої реєстрації.
8. «Мої групи» → від’єднати одну групу: друга працює далі, голосування першої закриті. Повторне підключення не відкриває їх знову.

## Межі першої версії

Кілька груп з окремими реєстрами, один адміністратор. Одне голосування публікується в одну обрану групу. Одна чернетка голосування адміністратора та одна поточна анкета кожного мешканця одночасно. Закриття вручну, без дедлайнів і нагадувань. Підтвердження квартири виконує адміністратор; бот не перевіряє документи. Це побутові опитування. Адміністратор і оператор бази технічно мають доступ до голосів; анонімність не заявляється.

Повторні доставлені updates обліковуються в D1. Унікальні обмеження захищають голос квартири та повторне створення запису голосування. Відправка повідомлення Telegram і запис у D1 не є однією транзакцією: за рідкісного збою між ними можливе повторне сповіщення/публікація. Незавершені заявки мешканців можна відкрити через `/pending`, заявки груп — через «Мої групи». Видалення даних і зміна підтвердженої квартири поки виконуються оператором D1; перед реальною експлуатацією визначте термін зберігання й порядок таких звернень.
